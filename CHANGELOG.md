# Changelog

All notable changes of this addon. The version number lives in
`freecad/SelectionInterfaceForLLM/version.py` and must match `<version>` in
`package.xml`; the Addon Manager compares `package.xml` only.

## 2.3.1 - 2026-11-08

A kept view is now a clean view, and the box sits with the other boxes.

- Ticked, `keep the build on closing` leaves the build **on screen at the step you
  were looking at, but opaque and without the profile sketch**: the thick orange
  line, the highlighted profile sketch (its own visibility, line width and colour
  are given back) and the see-through transparency raised on the selected step's
  body are all undone. Only the *build* is kept, not the browsing aids — measured
  on `_02_seringue_cardanV3` at step 31: 27 transparency values reset and 3 sketch
  properties restored, while the step's features stay visible.
- The box moved out of the bottom of the panel into a new **`options`** group
  directly under `show also`, together with `select in the model tree`, so no
  checkbox dangles under the buttons any more. Its label is now
  `keep the build on closing`.

## 2.3.0 - 2026-11-08

Keep the display when you close the panel.

- New checkbox **`keep the view on closing`**, unticked by default. Ticked,
  closing the panel leaves the 3D view exactly as it was displayed at that step
  (visibility, display mode, transparency, sketch colours, selection) instead of
  giving the document its own view back, so you can go on working on the part as
  it was shown. The document is still never saved, and `restore original` (or the
  box unticked) still brings the document's own state back.
- The temporary thick orange profile line is always removed on close, even with
  the box ticked: it is drawn in the 3D view rather than in the document, so it
  would stay on stale geometry as soon as the sketch it follows is edited. What
  the box keeps is the document's own view state.
- Report view gets one line saying which of the two happened.

## 2.2.0 - 2026-11-08

Selecting a step now selects it in the model tree, so a feature or its sketch can
be edited straight away instead of being described to an LLM.

- **The model tree follows the step**: clicking a row (or `step >`, `< step`, the
  spin box, `reset`, `final`) expands the tree down to the object of that step,
  scrolls the row into view and selects it. What gets selected is what is
  displayed: the **sketch** that drives the feature when the profile is shown
  (that is where the dimensions live), otherwise the feature, otherwise the datum
  plane. Measured on `guide_percage26`: step 1 selects `Sketch`, step 2 selects
  `trou` (the sketch carrying the hole diameter), step 3 selects `Sketch002`,
  datum steps select their datum, and the tree opened 3 branches for the first
  step.
- **`select in the model tree`** checkbox, ticked by default, switches it off for
  people who want to browse without touching their own selection.
- **The previous selection is given back** by `restore original`, by closing the
  panel and at the end of a GIF run, like every other thing the panel changes.
- **GIF frames can no longer carry a selection highlight**: `create GIF` clears
  the selection before the sweep and restores it afterwards. Measured: selecting
  one object changes 18 436 pixels of a 900x640 capture, and a per-frame probe
  recorded an empty selection at all 7 capture calls of a panel run started with
  an object selected.
- Robustness learned the hard way: FreeCAD 1.1.4 deletes and recreates every
  `Gui::TreeWidget` item whenever the document changes, so a held item raises
  `Internal C++ object ... already deleted`. The helpers now fetch the item with
  one `findItems()` call, let the event loop run first, and retry the
  find-then-use sequence on `RuntimeError`.

## 2.1.1 - 2026-11-08

Discoverability round — no change to the panel, the ordering or the GIF export.

- **Manifest description and tags rewritten for search.** The description now opens with
  "Build timeline of a PartDesign document" and names construction order, GIF and LLM; the
  tags gained `Timelapse`, `Sketch` and `GIF`. This matters because the addon index stores
  only repository URLs — the `package.xml` strings *are* what the Addon Manager searches.
- **Repository topics**: 15 topics (build-order, timelapse, feature-history, animation, gif,
  sketch, datum-planes, llm, …) so the project is reachable from a GitHub search.
- **README first screen**: the build-up GIF at the top
  (`resources/docs/preview_build.gif`, generated by the addon on `guide_percage26.FCStd`),
  the one-paragraph pitch, the "never saves / restores everything" line, and a search-word
  line.
- **`PUBLISH.md`**: the publicity kit — why the addon cannot be found yet, the name
  recommendation (`Build Steps` for a future release, nothing renamed here), the keyword map,
  paste-ready announcements (English and French forum posts, Reddit, Discord, the
  index-submission issue body), the visual assets, and the renaming procedure.
- **`resources/docs/Overview.md`** ends with its search words, for the documentation URL.

## 2.1.0 - 2026-11-08

Addon packaging round: the same tool, now a real FreeCAD addon.

- **Modern addon layout**: the code moved to `freecad/SelectionInterfaceForLLM/`
  (`__init__.py`, `init_gui.py`, `commands.py`, `workbench.py`, `interface.py`,
  `resources/`), so it no longer needs `sys.path` tricks and no longer pollutes the
  global module namespace.
- **A workbench instead of a macro**: "Selection interface" appears in the workbench
  selector with two commands, `Building steps panel` and `GIF of the whole build`.
  The `.FCMacro` is kept in `dev/` as a developer shim only.
- **`package.xml`, `pyproject.toml`, `LICENSE-Code` (LGPL-2.1-or-later),
  `LICENSE-Assets` (CC-BY-SA-4.0), SPDX headers and an SVG icon** for the Addon
  Index, with `<freecadmin>1.1.0</freecadmin>` (tested on 1.1.4 only).
- **Cross-platform file opening**: `os.startfile` and `explorer.exe /select` are
  replaced by `QDesktopServices.openUrl` with a per-platform fallback, so the addon
  is not Windows-only any more. `reveal_in_explorer` is now
  `reveal_in_file_manager`.
- **LLM handoff is now a file as well as the clipboard**: the request is written to
  `<Downloads>/FreeCAD_timelapse/llm_requests/` and its path is shown in the status
  line, and the request gained a section 0 explaining the tooling an agent should
  use (its own FreeCAD skill/MCP bridge, `freecadcmd` headless checks, asserting on
  printed values) while stating that the addon ships no skill and calls no service.
- Version number single-sourced in `version.py`.

## 2.0.0 - 2026-11-08

- Renamed from *Timelapse features* to *Selection interface for LLM*: folder,
  library module, macro file, dock title, Qt object names and the console prefix.
  Behaviour unchanged; the GIF is still written as `timelapse_<label>.gif` under
  `Downloads/FreeCAD_timelapse/` so existing run folders keep working.

## 1.7.0 - 2026-11-08

- The profile of the selected feature is drawn as a thick orange line: the driver
  clamps `LineWidth` (measured 709/850/1017/1219 orange pixels for width 1/3/6/10,
  `PointSize` ignored), so the sketch edges are rebuilt as small tubes in the Coin
  scene graph, wrapped in `SoAnnotation`, sized from the camera zoom
  (`PROFILE_LINE_PIXELS = 5.5`), never added to the document, and dropped by
  restore / close / document switch / GIF frames.

## 1.6.0 - 2026-11-08

- New "base / fused results" checkbox (unticked by default): a `PartDesign::FeatureBase`
  or a `Part::MultiFuse`/`Part::Fuse` is drawn only at its own step and the objects it
  absorbs are hidden from then on, which removes the coincident duplicate surfaces that
  looked like a mesh (measured: feature base, fusion and both halves are the same
  99563.843 mm3 solid, 100.00 % common volume).
- See-through now also applies to such a step, so what it swallows stays visible.

## 1.5.0 - 2026-11-08

- "show also" checkboxes (datum objects, profile sketch, other bodies), all ticked by
  default.
- Ordering fix: a mirror or a boolean that consumes a whole body is sorted after that
  body is completely built (on a 68-step assembly the mirrors moved from steps
  4/10/19/28 to 37/57/58/59, with the step count unchanged).

## 1.4.0 - 2026-11-08

- Display-style selector (solid + edges, solid, edges only, transparent, points),
  display of datum planes and of the driving sketch, per-level display contract built
  on `DisplayModeBody = 'Through'`.

## 1.3.0 - 2026-11-08

- Note box and "copy to clipboard description for LLM", with a feature-type-agnostic
  description of the selected feature and the document's full computation order.

## 1.0.0 - 2026-11-08

- First working version: computation order recovered from the dependencies and the
  tip chain, step-by-step panel, GIF export with blank-frame rejection and
